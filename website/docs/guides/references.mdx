# References and resolution

When building the object model, create the reference type for the element being referenced and give it an AsyncAPI reference URI. For example, a server can refer to a reusable component server:

```csharp
using System.Collections.Generic;
using ByteBard.AsyncAPI;
using ByteBard.AsyncAPI.Models;

var document = new AsyncApiDocument
{
    Info = new AsyncApiInfo { Title = "My document", Version = "1.0.0" },
    Servers = new Dictionary<string, AsyncApiServer>
    {
        ["production"] = new AsyncApiServerReference("#/components/servers/shared"),
    },
    Components = new AsyncApiComponents
    {
        Servers = new Dictionary<string, AsyncApiServer>
        {
            ["shared"] = new AsyncApiServer
            {
                Host = "example.com",
                Protocol = "https",
            },
        },
    },
};

var yamlV2 = document.SerializeAsYaml(AsyncApiVersion.AsyncApi2_0);
var yamlV3 = document.SerializeAsYaml(AsyncApiVersion.AsyncApi3_0);
```

The V2 writer emits the reference and its target component, for example:

```yaml
asyncapi: 2.6.0
info:
  title: My document
  version: 1.0.0
servers:
  production:
    $ref: '#/components/servers/shared'
components:
  servers:
    shared:
      url: example.com
      protocol: https
```

The V2 server fields are `url` and `protocol`; the host is not serialized as `https://example.com`. Serialize to V3 by choosing `AsyncApiVersion.AsyncApi3_0` instead. References created in a model are reference objects, not eagerly replaced by their target. Resolution is performed when a serialized specification is read; serializing a model alone does not resolve it for later object-model access.

## Read a resolved reference

Internal references are resolved by default during document reading. This covers component references such as `#/components/servers/shared` and document locations outside components, such as `#/servers/production`. The reference object remains a typed proxy: its target properties can be read directly, while `Reference.Reference` retains the URI and `UnresolvedReference` reports whether the target was found.

A local reference is a JSON pointer ([RFC 6901](https://www.rfc-editor.org/rfc/rfc6901)) into the document, so it can point at any location, not only at components: for example `#/channels/userSignup/messages/signedUp` or `#/servers/production/variables/port`. A key that contains `/` or `~` must be escaped as `~1` or `~0`. A channel keyed `user/signedup` is referenced as `#/channels/user~1signedup`; the unescaped `#/channels/user/signedup` points at a `signedup` member inside a `user` channel instead, and does not resolve.

Because a reference is a URI, its pointer is also percent-decoded before it is evaluated. `#/servers/a%20b` and `#/servers/a b` both refer to a server keyed `a b`, and resolve to the same server. A key that contains `%` itself must encode it as `%25`: a server keyed `a%20b` is referenced as `#/servers/a%2520b`. References the library writes for such keys, for example when converting between versions, are percent-encoded the same way.

Reference resolution is part of reading a full document with `Read`; `ReadFragment<T>` parses a fragment but does not run the document reference-resolution pass. A missing or invalid internal target is reported in diagnostics and remains unresolved.

```csharp
using System;
using ByteBard.AsyncAPI.Models;
using ByteBard.AsyncAPI.Readers;

var yamlV3 = """
asyncapi: 3.0.0
info:
  title: My document
  version: 1.0.0
servers:
  production:
    $ref: '#/components/servers/shared'
components:
  servers:
    shared:
      host: example.com
      protocol: https
""";
var parsed = new AsyncApiStringReader().Read(yamlV3, out var diagnostics);
var production = parsed.Servers["production"];

if (production is AsyncApiServerReference serverReference)
{
    // Host is proxied from the target server after successful internal resolution.
    Console.WriteLine(serverReference.Host);                       // example.com
    Console.WriteLine(serverReference.UnresolvedReference);       // False
    Console.WriteLine(serverReference.Reference.Reference);       // #/components/servers/shared
}
```

Consumers can often read a resolved proxy as the referenced type without first copying or replacing it. Keep the reference-type and resolution checks when your code requires a concrete target. For an unresolved reference, proxy getters can return `null`; avoid relying on target properties until `UnresolvedReference` is false. Reader errors and warnings are returned in `diagnostics`.

## Write references

References are written as references, including ones whose target could not be resolved, so they are not lost. To write local references as their target instead, set `ReferenceInline` on the writer settings. External references are always written as references. With `InlineReferences`, a local reference that cannot be resolved throws an `AsyncApiWriterException`.

```csharp
using System.IO;
using ByteBard.AsyncAPI.Models;
using ByteBard.AsyncAPI.Writers;

var settings = new AsyncApiWriterSettings
{
    ReferenceInline = ReferenceInlineSetting.InlineReferences,
};

using var stream = new MemoryStream();
document.SerializeAsYaml(stream, AsyncApiVersion.AsyncApi3_0, settings);
```

A reference to a location the written document does not contain is written inline, even without `InlineReferences`. This happens when converting between versions: a 2.x reference to `#/channels/userSignup/publish/message` has no equivalent location in 3.x, and a 3.x reference to `#/operations/sendUserSignup/traits/0` has none in 2.x. References that still resolve in the written document, such as references to components or servers, stay references. AsyncAPI 2.x cannot reference tags or external documentation, so those are written inline when writing 2.x. See [version conversion](./version-conversion) for the other differences.

## External references

`AsyncApiReaderSettings.ReferenceResolution` controls which references are resolved:

| `ReferenceResolutionSetting` | Local references | External references |
| --- | --- | --- |
| `ResolveInternalReferences` (default) | resolved | unresolved placeholders |
| `ResolveAllReferences` | resolved | loaded and resolved |
| `DoNotResolveReferences` | unresolved placeholders | unresolved placeholders |

The built-in loader supports absolute `file://`, `http://`, and `https://` URIs. Relative external URIs require a `BaseUri`; the built-in loader resolves them relative to that URI as file paths. Other URI schemes require a custom loader.

External resources are parsed as YAML or JSON and normalized through the reader's JSON representation before selecting any reference fragment. This does not support arbitrary serialization formats. For example, a loader can provide an in-memory YAML resource:

```csharp
using System;
using System.IO;
using System.Text;
using System.Threading.Tasks;
using ByteBard.AsyncAPI.Readers.Interface;

public sealed class StringDocumentLoader : IStreamLoader
{
    private readonly string content;

    public StringDocumentLoader(string content) => this.content = content;

    public Stream Load(Uri baseUri, Uri uri) =>
        new MemoryStream(Encoding.UTF8.GetBytes(this.content));

    public Task<Stream> LoadAsync(Uri baseUri, Uri uri) =>
        Task.FromResult(this.Load(baseUri, uri));
}
```

Register it with the reader settings. The example URI uses a custom scheme because this loader handles the resource itself; the built-in loader does not support `memory://`.

```csharp
using System;
using ByteBard.AsyncAPI.Models;
using ByteBard.AsyncAPI.Readers;

var externalYaml = """
asyncapi: 2.6.0
info:
  title: Shared servers
  version: 1.0.0
servers:
  shared:
    url: broker.example
    protocol: mqtt
""";
var input = """
asyncapi: 2.6.0
info:
  title: Client
  version: 1.0.0
servers:
  remote:
    $ref: 'memory://reference.example/servers.yaml#/servers/shared'
""";

var settings = new AsyncApiReaderSettings
{
    ReferenceResolution = ReferenceResolutionSetting.ResolveAllReferences,
    ExternalReferenceLoader = new StringDocumentLoader(externalYaml),
};
var parsed = new AsyncApiStringReader(settings).Read(input, out var diagnostics);
if (parsed.Servers["remote"] is AsyncApiServerReference remote &&
    !remote.UnresolvedReference)
{
    Console.WriteLine(remote.Host); // broker.example
}
```

`IStreamLoader` has synchronous `Load(Uri baseUri, Uri uri)` and asynchronous `LoadAsync(Uri baseUri, Uri uri)` methods; implement both for the reader APIs and return a readable stream containing the resource. `BaseUri` is passed to the loader for relative references. If an external resource cannot be fetched or parsed, the reader records a diagnostic and the reference can remain unresolved. Check both diagnostics and `UnresolvedReference` before relying on an external target.

## Disable resolution

Set `DoNotResolveReferences` to leave both internal and external references as placeholder reference objects:

```csharp
using System;
using ByteBard.AsyncAPI.Models;
using ByteBard.AsyncAPI.Readers;

var settings = new AsyncApiReaderSettings
{
    ReferenceResolution = ReferenceResolutionSetting.DoNotResolveReferences,
};
var unresolvedInput = """
asyncapi: 2.6.0
info:
  title: Client
  version: 1.0.0
servers:
  production:
    $ref: '#/components/servers/shared'
components:
  servers:
    shared:
      url: broker.example
      protocol: mqtt
""";
var parsed = new AsyncApiStringReader(settings).Read(unresolvedInput, out var diagnostics);
if (parsed.Servers["production"] is AsyncApiServerReference serverReference)
{
    Console.WriteLine(serverReference.Reference.Reference);
    Console.WriteLine(serverReference.UnresolvedReference); // True
}
```

See [version conversion](./version-conversion) for how references may be reorganized when serializing between AsyncAPI versions.
